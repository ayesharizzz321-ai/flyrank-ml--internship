## 1. How to Add the Next Case Study (Replicable Protocol)

Future project updates will follow a standardized 3-beat structure to maintain consistency across the portfolio platform:

### Directory Path & Navigation Update
* **File Location:** Save new projects as Markdown files in `docs/projects/<project-slug>.md`.
* **Navigation Map:** Register the new route in `mkdocs.yml` under `Projects` and feature a preview card on the home page.

### 3-Beat Case Study Format
1. **Beat 1: The Problem & Framing**
   * Specify the business/technical problem, domain context, dataset grain, unit of analysis, and target evaluation metrics.
2. **Beat 2: What Was Done (Methodology & Implementation)**
   * Document feature engineering steps, baseline comparisons, and model pipeline architecture.
   * Attach unedited screenshots of model evaluations (e.g., confusion matrices, feature importance plots, ROC curves).
3. **Beat 3: What Came Of It (Results & Impact)**
   * Present quantifiable performance outcomes (accuracy, ROC-AUC, latency improvements) alongside direct links to executed notebooks and public GitHub repositories.
