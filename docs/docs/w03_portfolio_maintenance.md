## 1. How to Add the Next Case Study (Replicable Protocol)

When adding any future project to this portfolio, follow this step-by-step workflow using the standard 3-beat structure:

### Target Directory & Navigation Insertion
* **File Location:** Create a new Markdown page under `docs/projects/<project-slug>.md`.
* **Site Navigation:** Add the new page route to the `mkdocs.yml` (or site configuration file) under the `Projects` navigation tree and feature it on the landing page project grid.

### 3-Beat Case Study Structure
1. **Beat 1: The Problem & Framing**
   * Define the domain context, dataset grain, unit of analysis, and target metric.
   * State the primary baseline challenge or business constraint.
2. **Beat 2: What Was Done (Methodology & Implementation)**
   * Show clean code snippets, feature engineering choices, and model selection.
   * Include unedited, cropped real screenshots of confusion matrices, ROC curves, or data outputs.
3. **Beat 3: What Came Of It (Results & Impact)**
   * State quantifiable results (e.g., accuracy, ROC-AUC, latency improvements, inference speed).
   * Include a direct link to the public GitHub code repository or Colab notebook.
